# PreProc-2 — параметры, имена файлов и очередь

## Параметры задачи

`GeneralParameters` определён в Project: [исходник](../../Project/TaskParameters/GeneralParameters.cs) и [диаграмма](../../Project/Documents/Project-2.mdpuml). PreProc присваивает `Index` при подготовке каждого временного интервала. В базовом классе уже находятся `TaskKind` и `TimeSettings`. Переопределённый `ToString()` выдаёт основу имени `вид_индекс_начало_конец`, например `термическая_1_0_0.25`. Время форматируется как G9 с InvariantCulture; допустима экспоненциальная запись. TSF и ожидаемый DB получают одинаковую основу имени и расширения `.tsf` и `.db` соответственно.

Числовой индекс положительный. Времена конечные и неотрицательные, конец не раньше начала. Эти условия проверяются при подготовке параметров и при чтении строки очереди писателем TCF. Время в имени не определяет порядок задач.

## Строки очереди

Формат строки, которую клиент передаёт `WriteCommandFile`: `вид путь-TSF статус`. Например, `термическая InputData/термическая_1_0_0.25.tsf выполнить`. Путь отсчитывается от корня комплекта и может содержать пробелы; первое поле задаёт вид задачи, последнее — статус, всё между ними является путём. Разбор и проверка находятся в `TcfWriter`, тип элемента очереди не вводится. Имя TSF обязано соответствовать виду задачи в строке.

`TaskStatus` ([исходник](../PreProc.cs)) принимает `выполнить` и `пропустить`. Запись TCF сохраняет порядок и статусы входных строк. Повтор пары `(вид задачи, индекс)` отвергается даже при разных временах. На этапе первоначального создания PreProc выдаёт параметры по числовому индексу, а для одинакового индекса — сначала термическую, затем механическую задачу. Дальнейший порядок задаёт клиентский TreeView.

Переходный метод `SortCompDataByTimeAndType` всё ещё принимает пути TSF и возвращает строки указанного формата для существующего GUI. Он сортирует по числовому индексу; неверные имена и повторы отклоняет. После подключения Gerbera к новому API этот метод можно убрать.
