# PreProc-3 — TCF и относительные пути

[Диаграмма](PreProc-3.mdpuml) · [Обзор](PreProc.md) · [API подготовки](PreProc-1.md) · [Очередь и имена](PreProc-2.md).

## Файловый контракт

Корень — каталог существующего сохранённого .bpf или .bpf2. Подкаталоги: InputData для TSF, ResultsData для DB, ComputationData для TCF. Препроцессор не создаёт сами результаты DB.

| Источник | Ссылка | База разрешения |
| --- | --- | --- |
| Строка очереди клиента | `InputData/термическая_1_0_0.25.tsf` | Корень комплекта |
| TCF | `../project.bpf2` | Каталог TCF |
| TCF | `../InputData/термическая_1_0_0.25.tsf` | Каталог TCF |
| TSF, InitialSet.File / InputSets[].File | `../ResultsData/термическая_1_0_0.25.db` | Каталог содержащего TSF |

Все сериализованные файловые ссылки относительные, используют / и остаются внутри комплекта. Двухаргументный метод подготовки параметров не пишет TSF; клиент Gerbera должен сохранять их по этому контракту при последующем подключении. В TCF входной путь TSF относителен корню комплекта, путь проекта может быть абсолютным. Проверяются непереносимые символы, имена с точкой/пробелом на конце и зарезервированные Windows-имена. Несовпадение регистра любого существующего сегмента внутри комплекта отклоняется на обеих ОС. Проверка границ выполняется по нормализованным путям; защита от перенаправления символическими ссылками не заявляется.

Писатель TCF использует UTF-8 без BOM. Пример содержимого ComputationData/computation.tcf:

```text
загрузить проект "../project.bpf2"
расчет термическая "../InputData/термическая_1_0_0.25.tsf" выполнить
расчет механическая "../InputData/механическая_1_0_0.25.tsf" пропустить
```

Пути всегда заключаются в двойные кавычки. Имя результирующего TCF фиксировано: computation.tcf. Переносится весь комплект с сохранением взаимного расположения файлов. Новый контракт должен отдельно поддержать читатель Solver; текущий Solver здесь не изменён. Старый формат не поддерживается.

## TcfWriter

[Исходник](../TcfWriter.cs). Публичный экземплярный класс пространства имён PreProc.

```text
Write(string projectPath, IEnumerable<string> queueRows) : string
```

Разбирает строки очереди `вид путь статус`. Проверяет существование проекта и всех перечисленных TSF, включая пропущенные, соответствие вида задаче в имени файла, допустимость статусов, отсутствие null, непустоту очереди и уникальность пары вида/индекса. При этом содержимое TSF и физические зависимости задач не проверяет. Не требует наличия будущих DB.

Очередь полностью перечисляется и проверяется до замены TCF. Затем создаётся каталог, записывается временный файл в нём и заменяется целевой TCF. Остаток временного файла удаляется в finally. При ошибке проверки существующий TCF остаётся прежним. Транзакционная замена всего комплекта и проверка результата расчёта в обязанности писателя не входят.

Писатель не сортирует очередь, не изменяет статусы и TSF. Это самостоятельная операция для клиента по нажатию «Старт».

## CalculationPaths — внутренний компонент

[Исходник](../CalculationPaths.cs). internal class пространства имён PreProc; публичным клиентским контрактом не является.

```text
GetProjectRoot(string projectPath) : string
GetRelativeFile(string root, string sourceDirectory, string targetPath, bool requireExisting) : string
```

Первый метод проверяет сохранённый проект и возвращает корень. Второй разрешает путь относительно каталога источника, проверяет размещение в комплекте и переносимость компонентов имени, при необходимости проверяет существование файла, возвращает относительную ссылку с /.

TCF проверяет проект и TSF с requireExisting = true. Ссылки на будущие DB формируются при подготовке параметров и не требуют существования файла.
