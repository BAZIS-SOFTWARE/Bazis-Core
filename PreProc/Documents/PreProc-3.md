# PreProc-3 — чтение и запись TCF/TSF

[Диаграмма](PreProc-3.mdpuml) · [Обзор](PreProc.md) · [API подготовки](PreProc-1.md) · [Очередь и имена](PreProc-2.md).

## Файловый контракт

Корень — каталог существующего сохранённого .bpf или .bpf2. Подкаталоги: InputData для TSF, ResultsData для DB, ComputationData для TCF. Препроцессор не создаёт сами результаты DB.

| Источник | Ссылка | База разрешения |
| --- | --- | --- |
| TCF | `../project.bpf2` | Каталог TCF |
| TCF | `../InputData/термическая_0_0_0.25.tsf` | Каталог TCF |
| TSF, InitialSet.File / InputSets[].File | `../ResultsData/термическая_0_0_0.25.db` | Каталог содержащего TSF |

Ссылки TCF относительные, используют / и остаются внутри комплекта. Метод подготовки параметров не пишет TSF; при запуске `TcfWriter` сериализует все объекты очереди в `InputData`. При открытии комплекта `TcfReader` разрешает ссылки TSF относительно каталога TCF. Путь проекта при вызове PreProc может быть абсолютным. Проверяются непереносимые символы, имена с точкой/пробелом на конце и зарезервированные Windows-имена. Несовпадение регистра любого существующего сегмента внутри комплекта отклоняется на обеих ОС. Проверка границ выполняется по нормализованным путям; защита от перенаправления символическими ссылками не заявляется.

Писатель TCF использует UTF-8 без BOM. Пример содержимого ComputationData/computation.tcf:

```text
загрузить проект "../project.bpf2"
расчет термическая "../InputData/термическая_0_0_0.25.tsf" выполнить
расчет механическая "../InputData/механическая_0_0_0.25.tsf" пропустить
```

Пути всегда заключаются в двойные кавычки. Имя результирующего TCF фиксировано: computation.tcf. Переносится весь комплект с сохранением взаимного расположения файлов. Новый контракт должен отдельно поддержать читатель Solver; текущий Solver здесь не изменён. Старый формат не поддерживается.

## TcfWriter

[Исходник](../TcfWriter.cs). Публичный экземплярный класс пространства имён PreProc.

```text
Write(string projectPath, IEnumerable<GeneralParameters> parameters) : string
```

Принимает очередь объектов `GeneralParameters`. Проверяет существование проекта, допустимость видов задач, индексов, времён и статусов, отсутствие null, непустоту очереди и уникальность пары вида/индекса. Ссылки будущих DB не требуют существования файла.

Очередь полностью перечисляется и проверяется до файловой записи. Затем записываются TSF всех задач в UTF-8 без BOM, в том числе со статусом `пропустить`. TCF записывается во временный файл и заменяет целевой; остаток временного файла удаляется в `finally`. При ошибке проверки существующий TCF остаётся прежним. Транзакционная замена всего комплекта и проверка результата расчёта в обязанности писателя не входят.

Писатель не сортирует очередь и не изменяет статусы объектов. Клиент вызывает отдельную операцию `WriteInstructions` при «Старт».

## TcfReader

[Исходник](../TcfReader.cs). Внутренний экземплярный класс пространства имён PreProc.

```text
Read(string projectPath) : IEnumerable<GeneralParameters>
```

Читает фиксированный `ComputationData/computation.tcf`, проверяет команду проекта, порядок и синтаксис команд расчёта, разрешает пути TSF и проверяет наличие файлов. TSF десериализуются по виду задачи; вид, индекс и времена сверяются с именем файла, повтор вида и индекса отклоняется. Статус берётся из команды TCF. Метод возвращает ленивое перечисление; `PreProc.Load` материализует его до замены текущей очереди.

## CalculationPaths — внутренний компонент

[Исходник](../CalculationPaths.cs). internal class пространства имён PreProc; публичным клиентским контрактом не является.

```text
GetProjectRoot(string projectPath) : string
GetAbsoluteFilePath(string sourceDirectory, string referencePath) : string
ValidatePortableFilePath(string root, string targetPath) : void
GetRelativeFile(string sourceDirectory, string targetPath) : string
```

Первый метод проверяет сохранённый проект и возвращает корень. `GetAbsoluteFilePath` только разрешает ссылку относительно каталога источника. `ValidatePortableFilePath` отдельно проверяет размещение в комплекте и переносимость компонентов имени. `GetRelativeFile` формирует относительную ссылку с /. Существование TSF при чтении проверяет `TcfReader` после получения абсолютного пути.

Ссылки на будущие DB формируются при подготовке параметров и не требуют существования файла.
