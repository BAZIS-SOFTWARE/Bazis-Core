# Сборка PDF с навигацией по диаграммам

`build_pdf.py` собирает любой выбранный набор `.mdpuml`, `.puml` и `.svg` в многостраничный PDF. Векторные схемы, ссылки между ними, закладки, оглавление и возврат к обзору сохраняются. Соседние `.md` и описания, на которые ссылаются схемы, включаются отдельными разделами; ссылки на них становятся внутренними переходами PDF. Поддерживается основной формат документации репозитория: абзацы, заголовки, выделения, таблицы, ссылки и блоки кода.

## Подготовка

Нужен Python 3.10+ и библиотеки из `requirements-pdf.txt`. Их можно установить в отдельное окружение, без изменения системного Python:

```powershell
python -m venv .codex/tools/.venv
& .codex/tools/.venv/Scripts/python.exe -m pip install -r .codex/tools/requirements-pdf.txt
```

В примерах ниже `python` обозначает интерпретатор с установленными зависимостями. Для отдельного окружения замените его на `& .codex/tools/.venv/Scripts/python.exe`. В текущем рабочем каталоге это окружение уже подготовлено; оно исключено из Git.

Сборщик использует шрифты Arial и Consolas из `C:/Windows/Fonts`. Другой каталог с этими TTF можно указать через `--font-dir`.

Для PlantUML по умолчанию используется сервер `http://192.168.11.202:8080`, указанный в инструкции архитектора. Адрес можно изменить через `--server`. Для готовых SVG сервер не нужен.

## Примеры запуска из корня BazisCore

Начать с обзора и включить все связанные схемы:

```powershell
python .codex/tools/build_pdf.py Model/Documents/Model.mdpuml --include-linked --output output/pdf/Model.pdf --title "Model"
```

Выбрать конкретные схемы из разных проектов:

```powershell
python .codex/tools/build_pdf.py Model/Documents/Model-1.mdpuml PrGeometry/Documents/Geometry-1.mdpuml --include-linked --output output/pdf/Selected.pdf
```

Собрать только страницы схем без разделов Markdown:

```powershell
python .codex/tools/build_pdf.py "Model/Documents/*.mdpuml" --include-linked --no-markdown --output output/pdf/Model-diagrams.pdf
```

Принять все схемы из папки (без рекурсивного обхода подпапок):

```powershell
python .codex/tools/build_pdf.py Project/Documents --include-linked --output output/pdf/Project.pdf --title "Project"
```

SVG и ссылки с одинаковыми именами файлов в разных папках поддерживаются:

```powershell
python .codex/tools/build_pdf.py "first/Overview.svg" "second/Overview.svg" --offline --output output/pdf/Overview.pdf
```

## Разрешение ссылок

- Относительный адрес разрешается относительно исходного `.mdpuml`, `.puml`, `.svg` или `.md`, а не относительно каталога SVG-кэша.
- Идентификатор страницы зависит от полного пути. Одинаковые имена схем в разных каталогах не конфликтуют.
- `--include-linked` рекурсивно включает локальные схемы, на которые ссылаются исходники; циклы не создают повторных страниц. Ссылки для обхода берутся из `[[...]]` в PlantUML, `<a>` в SVG и ссылок соседних Markdown-документов.
- Без `--include-linked` каждая локальная ссылка на диаграмме должна вести в выбранный набор. При отсутствии цели сборка завершается с указанием исходника и ссылки до перезаписи выходного PDF.
- В режиме `--no-markdown` ссылки вида `A.md` ведут к включённой диаграмме `A.mdpuml`, `A.puml` или `A.svg`. Если такой схемы нет, сообщается ошибка.
- Ссылки на заголовки Markdown, например `A.md#контракт`, ведут к странице соответствующего раздела.
- Внешние сетевые URL сохраняются как внешние ссылки. Ссылки из текста Markdown на исходники, не включённые в PDF, печатаются как обычные подписи. Локальные ссылки схем не превращаются в обращения к файлам на диске.
- Схемы с `caption АРХИВ` исключаются. Явно выбранные схемы сохраняют заданный порядок; папки и автоматически добавленные поддиаграммы упорядочиваются с учётом числовых суффиксов.

SVG-преобразования и смещение `viewBox` учитываются при расчёте кликабельных областей. Страницы схем увеличиваются по содержимому, без уменьшения текста до нечитаемого размера. `--font-size` задаёт минимальный размер текста схемы в пунктах PDF; по умолчанию 10. Если схема превышает допустимый размер страницы PDF, сборщик предлагает разделить её.

## Кэш и работа без сети

SVG, полученные от сервера, сохраняются в `.pdf-cache` рядом с результатом. Другой каталог задаётся через `--cache-dir`. Ключ включает путь и SHA-256 исходного текста; изменённая схема требует нового рендера.

Также можно использовать существующий `render-report.json`. SVG берётся из отчёта только при совпадении SHA-256 исходника и отсутствии ошибки рендера:

```powershell
python .codex/tools/build_pdf.py Model/Documents/Model.mdpuml --include-linked --offline --render-report "C:/Users/Georgy/AppData/Local/Temp/bazis-docs-tools/render-report.json" --output output/pdf/Model.pdf
```

Относительные поля `File` в отчёте разрешаются от корня репозитория; для чужого отчёта используется `--root`. `--offline` запрещает обращения к серверу: если актуального SVG нет, сборка завершается с объяснением.

## Проверка результата

Рядом с PDF создаётся `Имя.manifest.json`: состав исходников и их хеши, индекс страниц, адреса закладок, области ссылок со схем и строки сигнатур. Путь можно изменить через `--manifest`.

```powershell
python .codex/tools/verify_pdf.py output/pdf/Model.pdf
```

Проверяются хеши PDF и исходников, страницы, адреса и границы ссылок, полнота строк блоков кода, отсутствие ошибочных символов и текста за пределами страниц. Результат записывается в `Имя.verification.json`. Для SVG с намеренно встроенными растровыми изображениями предусмотрен `--allow-images`.

Для визуальной проверки нужен Poppler (`pdftoppm`):

```powershell
python .codex/tools/verify_pdf.py output/pdf/Model.pdf --render-dir tmp/pdfs/model-preview --pdftoppm "C:/path/to/pdftoppm.exe"
```

Скрипт рендерит страницы и создаёт обзорные листы. Это подготовка изображений для просмотра, а не автоматическая оценка качества оформления. Повторный рендер выполняйте в новом или очищенном каталоге, чтобы не смешивать изображения разных версий PDF.

## Тесты

```powershell
python -m unittest discover -s .codex/tools/tests -v
```

Проверяются одинаковые имена схем, обычный `href` и `xlink:href`, кириллица и URL-кодирование путей, циклические ссылки, отсутствующие цели, вложенные SVG-преобразования, `viewBox`, Markdown-разделы, длинные абзацы и сигнатуры, многостраничное оглавление, внешние ссылки и отсутствие актуального SVG в автономном режиме.
