# Контракт физических полей

Источник правил — раздел «Устойчивые интеграционные правила» в [AGENTS.md](../AGENTS.md). Этот документ описывает согласованный формат, а не утверждает, что все проверки уже реализованы.

## Наборы и обмен между задачами

| Физическая задача | Родной набор | Поля родного набора | Допустимые внешние наборы |
| --- | --- | --- | --- |
| Тепловая | Термический (`Thermal`) | `T`, `ph(x,t)` | Гидродинамический: `v,p,T(x,t)`; Химический: `C,T(x,t)` |
| Механика | Механический (`Mechanical`) | `u,σ,ε,T,ph(x,t)` | Термический: `T,ph(x,t)`; Химический: `C,T(x,t)`; Гидродинамический: `v,p,T(x,t)` |
| Гидродинамика | Гидродинамический (`Hydrodynamic`) | `v,p,T(x,t)` | Термический: `T,ph(x,t)` |
| Физхимия | Химический (`Chemical`) | `C,T(x,t)` | Термический: `T,ph(x,t)` |

`x` — координата, `t` — время. `GeneralParameters.InitialSet` хранит родной набор начального состояния, `InputSets` — внешние наборы. Для одного внешнего набора выбирается один источник: текущий `GetInputField` уже отклоняет несколько одноимённых источников. См. [GeneralParameters.cs](../Project/TaskParameters/GeneralParameters.cs).

## Хранение и источник

`PhysicalSet` содержит `Name`, `Source`, `Values` и `File`. Каждый набор имеет один источник.

| Источник | Значимые данные |
| --- | --- |
| Значения (`Values`) | Соответствие «группа → список физических величин и компонентов» |
| Файл (`ResultFile`) | Путь к файлу в `File` |

Группа может быть узловой или элементной; принадлежность `MatData` не ограничивает пользовательский выбор группы. Группы из `MatData` используются по умолчанию при формировании начальных условий связываемых задач.

В текущем DTO ключ `Values` — строковое имя группы, значение — список `PhysicalField`. `PhysicalField.Name` выбирает величину, `Components` содержит её компоненты. Строка вида `T 100,v 0,0,0` — представление для ввода/обмена; внутри DTO это разные именованные величины. Путь файла и значения разных источников не смешиваются. Исходник: [PhysicalSet.cs](../Project/TaskParameters/PhysicalSet.cs).

## Формат значений

Для группы записывается последовательность именованных величин, разделённых запятыми. После имени величины следуют её компоненты. Запятая также разделяет компоненты вектора или тензора, поэтому границу величины определяет следующее имя поля.

| Обозначение | Величина в DTO | Число компонентов |
| --- | --- | --- |
| `T` | `Temperature` | 1 |
| `ph` | `PhaseComposition` | По фазовому составу материала |
| `v` | `Velocity` | По размерности задачи |
| `u` | `Displacement` | По размерности задачи |
| `p` | `Pressure` | 1 |
| `C` | `Concentration` | 1 |
| `σ` | `Stress` | По размерности и постановке задачи |
| `ε` | `Strain` | По размерности и постановке задачи |

Примеры:

```text
Механический набор, группа: T 100,ph 0.7,0.3
Гидродинамический набор, группа 3D: v 1,0,0,p 101325
Термический набор, группа: T 0
Гидродинамический набор, группа 3D: v 0,0,0
```

В этих примерах неуказанные величины выбранного набора равны нулю. Пустая запись означает нулевые величины всего набора. Одиночная запись `0` ошибочна: имя поля обязательно при явном задании величины. `T 0` и `v 0,0,0` допустимы. Число компонентов должно соответствовать задаче; отсутствующая величина и явно заданный вектор неправильной длины — разные случаи.

## Порядок компонентов тензора

| Постановка | Порядок | Число компонентов |
| --- | --- | --- |
| 3D | `XX,YY,ZZ,XY,XZ,YZ` | 6 |
| 2D, осесимметричная | `XX,YY,ZZ,XY` | 4 |
| 2D | `XX,YY,XY` | 3 |
| 1D | `XX` | 1 |

Порядок одинаков для `σ` и `ε`. Спецификация не задаёт дополнительного соглашения о масштабировании сдвиговых компонент; его нельзя выводить только из списка обозначений.

## Подготовка инструкций и пределы реализации

В [PreProc.cs](../PreProc/PreProc.cs) `SetInitialFieldFromFile` и `SetInputField` переключают набор на источник файла и очищают `Values`. `GetParameters` формирует начальный набор по именам групп `MatData` и явно записывает `T = 20`. Это конкретное начальное условие препроцессора; оно не меняет правило нулевого значения отсутствующего поля.

`PhysicalSetName.Hydrodynamic` уже существует, но в `TaskKind` и `PreProc.GetNativeFieldSet` представлены только тепловая, механическая и химическая задачи. Полный путь гидродинамической задачи не реализован в этих контрактах. См. [ITaskData.cs](../Project/Interfaces/Tasks/ITaskData.cs) и [реестр расхождений](ArchitectureDifferences.md).

В просмотренных DTO и общих параметрах нет полного парсера и валидатора описанного строкового формата, числа фаз и тензорных компонент. Их поддержку в клиентах эта ревизия не проверяет. При реализации нужно отдельно проверить пустые значения, одиночный `0`, принадлежность поля набору, число компонентов, допустимость источников, существование узловых/элементных групп и порядок тензоров.
